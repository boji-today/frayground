# 01 后端：单进程四子棋

本文件只排列这一里程碑的实施顺序。产品范围以[纲领](../PROJECT_CHARTER.md)为准；规则见[四子棋](../game-rules/connect-four.md)，状态机见[领域模型](../03-domain-model.md)。

按已有的领域类、状态机和 DeepSeek 请求器拆分。每项都能单独开发、自测，并在审阅时检查明确的输入、输出和状态变化。内存实现先满足当前运行需求，接口和对象关系沿用现有 Room、Match、Decision、Settlement 等边界，为后续接入持久化留接口。

本里程碑到单进程内可运行、可观察的一局为止。本地数据库历史仍属于纲领中的 MVP，由后续持久化替换内存适配器完成，不在此处重写游戏规则与决策边界。

## 任务

1. **实现四子棋规则与编解码**  
   关注棋盘初始化、落子合法性、胜负/平局判定、观察和事件，以及状态、动作的 JSON 编解码。  
   **自测与审阅：** 覆盖边界列、满列、非法席位、横竖斜胜、平局和终局后拒绝行动；确认非法动作不修改原状态。

2. **补齐游戏注册与棋局初始化**  
   关注通过 GameKey 找到四子棋规则和 Codec，并创建 Room 的初始 Match、席位、状态快照和首个 Turn。  
   **自测与审阅：** 从注册表按规则版本找到实现；检查初始席位、先手和状态版本符合预期。

3. **提供内存版状态与记录适配器**  
   关注 Room、Match、Decision、Turn、快照、事件和回执的进程内保存，遵循现有仓储端口及身份、版本关系。  
   **自测与审阅：** 覆盖创建、读取、重复请求和重置后的新旧 Match 隔离；明确重启后数据不保留。

4. **打通 Agent 决策输入与本地测试运行时**  
   关注从当前合法观察、席位 Prompt 和配置构造决策请求，并提供确定性 Mock Runtime，方便离线跑通。  
   **自测与审阅：** 确认不同席位只收到各自观察、输入不追加历史；Mock 能稳定返回合法及非法动作样例。

5. **串起 Decision 生命周期与权威动作结算**  
   关注启动决策、固定版本与观察、接收结构化动作、再次校验、规则结算并更新事件、快照和 Decision 结果。  
   **自测与审阅：** 覆盖成功落子、非法动作失败、状态版本只在成功结算时递增、重复提交返回原回执。

6. **接通 DeepSeek Runtime 并处理调用结果**  
   关注复用现有 HTTP 适配器，将模型响应解析为四子棋动作，并映射超时、调用错误、解析错误和非法动作。  
   **自测与审阅：** 用模拟 HTTP 响应覆盖正常、异常和超时；确认失败可观察且不会修改棋盘或自动替选动作。

7. **实现房间调度与控制命令**  
   关注 start、pause、step、continue、reset 的既有状态机语义，以及暂停期间决策完成、单步许可和终局停机。  
   **自测与审阅：** 覆盖状态迁移、重复点击、暂停与决策竞争、单步只结算一个决策、重置隔离旧 Match。

8. **提供最小运行与观察 API**  
   关注创建/读取房间、提交控制命令、查看棋盘与过程事件，以及查看当前执行、Match 和 Decision 状态。  
   **自测与审阅：** 用 Web 层测试验证请求校验、响应结构、错误状态和观察数据；确保不直接暴露内部 Prompt、凭据或推理内容。

9. **完成双 Agent 对局闭环验收**  
   关注从启动房间到两个 Agent 轮流决策、结算、终局、暂停和重置的整条路径；可分别使用 Mock 与 DeepSeek 配置运行。  
   **自测与审阅：** 用 Mock 完整跑完一局并检查事件及结果；DeepSeek 路径确认可发起真实调用，失败时行为符合既定规则。

完成第 9 项后，backend 应能在单进程内运行和观察一局四子棋。
