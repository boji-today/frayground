# MVP 产品范围与验收

> 状态：已采纳的设计；2026-10-19。本文描述待实现能力，仓库当前没有可运行产品。产品原则以[项目纲领](PROJECT_CHARTER.md)为准，技术决定见[ADR](09-architecture-decisions.md)。

## 1. 用户与目标

第一版面向在本机运行平台的同一名操作者：配置双方 Agent，观察比赛，修改 Prompt，再次尝试。两个 Agent 是两个决策实体，不要求两个账号。实验室允许操作者查看双方 Prompt，不表示对手或观众长期拥有此权限。

验收闭环为：编辑策略 → 发布版本 → Agent 接收合法观察 → 生成结构化动作 → 平台验证并结算 → 观察记录与结果 → 重置再试。工程验收不代替 Prompt 可玩性验证。

## 2. 第一版交付边界

| 分类 | MVP 必须实现 | 仅设计边界或延后 |
| --- | --- | --- |
| 游戏 | 单实例、一个房间、两席四子棋；应用内 GameDefinition 注册 | 多人正式比赛、同时回合、机器人和资源游戏 |
| Agent | Mock、平台内 LLM Runtime；DeepSeek Flash 默认模型 | 远程 Pull/Push、SDK、工具编排、MCP/A2A |
| 策略 | 草稿、不可变发布版本、决策绑定、模型配置版本 | 策略市场、自动优化、A/B 调度 |
| 上下文 | 每次根据当前观察构造 STATELESS 输入 | RECENT_HISTORY、STRATEGY_MEMORY、RAG |
| 控制 | 开始、暂停、继续、单步、模式切换、中止当前决策、重置 | 多节点执行、自动重启续跑 |
| 观察 | 棋盘、记录、错误、Token 用量、历史局及最小逐步回放 | 永久托管回放、批量实验、排行榜 |
| 数据 | 本地 MySQL 8.4 LTS；完整初始化 SQL；重启恢复 | 自动迁移、自动清理、跨局 Agent 记忆 |

仅测试注册的减石子规则用于证明通用引擎无棋盘依赖，不作为第二款产品游戏开放。没有用户注册、付费、RBAC、第三方插件市场、微服务或分布式设施。

## 3. 确认的使用流程

1. 容器空数据卷首次初始化数据库；应用只连接数据库，普通启动不执行改表或种子脚本。
2. 打开实验室，获得唯一房间和初始 Match（READY、STEP、PAUSED）；双方初始 Runtime 为 MOCK，LLM 模型配置预置 `deepseek-flash`。
3. 在各面板编辑并保存草稿，点击“应用 Prompt”发布版本。保存草稿不改变已发布版本。
4. 点击“开始”自动运行，或“下一步”只执行当前一方的一次决策及结算。
5. 运行时点击暂停或切换 STEP，不取消已启动决策；当前决策结束后停住。忙碌期间重复下一步不增加许可。
6. 输出、解析或规则错误使比赛暂停；操作者可调整配置后点击继续或下一步，启动新 Decision。
7. “中止当前决策”作废当前决策并暂停；“重置”作废未结束的旧 Match，创建新 Match，保留配置和全部旧记录。
8. 选择历史局，以前一步/后一步查看棋盘和对应版本、输出与执行结果；返回实时视图后才能控制比赛。

## 4. 默认限制

- Connect Four，7 列 × 6 行，固定 A 先手，B 后手；平局、失败与胜负严格区分。
- LLM 默认非思考、非流式、JSON Mode；每次决策 30 秒（含上下文构建、调用和提交前处理），输出上限 256 Token；不自动重新生成。
- 模型单次调用的输入预算为 UTF-8 32 KiB，Prompt 文本上限 UTF-8 16 KiB；构造超限直接失败，不悄悄截断策略或观察。这是字节限制，不声称精确 Token 估算。
- 正常自动对局最多 42 次成功落子；人工失败后重试可能增加调用次数。无每局金额硬上限，只记录可获取的用量和估算依据。
- 缺少服务端 Key 时 LLM 配置检查失败，不能伪装成 Mock 成功；离线测试不需要 Key。
- 记录保留在本地数据卷，无自动清理。保留不等于云端永久保存；备份由操作者负责。

## 5. 验收标准

| 能力 | 可检验的完成条件 |
| --- | --- |
| 完整对局 | Mock 可从空棋盘走到胜利或平局，结果符合规则；终局后不启动决策 |
| 策略版本 | 推理中发布 v2 不改变当前 v1 决策；下次启动绑定 v2；历史可查实际版本 |
| 控制 | 暂停/STEP 与调度竞争时以服务端串行顺序为准；确认切换后无新许可泄漏；单步不走对方下一手 |
| 故障可观察 | 非法 JSON、非法动作、超时、限流均有决策错误，棋盘保持原状态并暂停 |
| 提交可靠 | 相同动作重试返回原结果；不同内容冲突；取消、重置或过期后的响应不能落子 |
| 数据 | 成功结算、快照、事件及回执原子提交；重启后棋盘与记录一致，保持暂停 |
| UI 同步 | 刷新/断线恢复后与服务端一致，编辑草稿不被推送覆盖 |
| 数据初始化 | 首次建库成功；已有数据卷重启不重放脚本、不覆盖玩家修改 |

策略敏感性另以固定局势、固定模型配置、多次采样和交换先后手的实验检验。单次动作差异不是胜率提升证据；四子棋用于技术验证，后续可提议小型资源分配游戏检验更丰富策略，未经确认不进入 MVP。
